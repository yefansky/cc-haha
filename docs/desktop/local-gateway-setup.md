# 本机浏览器配置网关接入

源码 Bun 服务提供 `/_local/gateway` 本机接入控制页，复用桌面客户端的原生隧道运行器。适用于没有 Electron 窗口、需要在本机浏览器完成网关接入配置的实验环境。

## 启动与配置

1. 使用隔离目录设置 `CLAUDE_CONFIG_DIR`，用至少 32 字符随机值设置 `CC_HAHA_LOCAL_ACCESS_TOKEN`。该凭据证明浏览器操作者能够读取本机启动环境，不能使用网关用户名/密码代替。
2. 仅绑定 `127.0.0.1`。本机实验启动器必须默认设置 `CC_HAHA_GATEWAY_LOCAL_ONLY=1`：此模式对上游整个 H5/API 统一认证，网关目标仅允许 literal-loopback 地址。
3. 确保已有随包原生 tunnel 客户端。开发者可用绝对路径 `CC_HAHA_GATEWAY_CLIENT_PATH` 指定发行客户端；页面不能填写可执行文件路径，以免变成任意命令执行入口。
4. 打开 `http://127.0.0.1:<端口>/_local/gateway`，用本机访问凭据登录。
5. 在网关页面使用管理员分配的账号登录并创建接入密钥，把网关设备接入地址（含端口，例如 `http://127.0.0.1:8081`）和接入密钥填入本机配置页，依次点击“保存接入配置”“测试连接”“启动连接”。手机登录页面的端口和设备接入端口可能不同。地址和密钥均通过页面配置，不需要改代码、数据库或服务器后台。
6. 在网关页面选择在线设备，进入 cc-haha H5 执行会话操作。这一步才是端到端业务验证；单独“测试连接”仅证明本机、网关及密钥/协议三层握手。

## 会话、密钥与控制面边界

- 本机登录 Cookie 为随机服务器会话，不包含本机 token 或 tunnel key；HttpOnly、SameSite=Strict、仅 `/_local/gateway` 路径，12 小时有效。刷新页面保留登录，注销或服务重启失效。
- Bun 进程没有 Electron safeStorage 桥接时，tunnel key 仅保存于服务内存，落盘配置只保存 URL 和非敏感元数据。服务重启后重新粘贴密钥，页面有明确提示。
- 本机控制面必须实际 loopback 来源、精确 Host、同源请求。跨 Origin、转发头、任何 gateway forwarder 均被服务端拒绝；所有配置写操作还验证 CSRF。
- 远程 H5 不允许配置本机网关、读取本机访问凭据或访问此控制面。只有本机页可以管理隧道进程。
- 本机实验使用 loopback HTTP；不会通过该页面把实验流量发送到外网。该模式不是公网部署方案。

## 构建客户端

客户端源码随本仓库保存在 `desktop/gateway-client`，不需要取得网关服务端仓库。在 `desktop` 目录执行 `bun run build:gateway-tunnel` 可构建当前系统的原生客户端；脚本在隔离环境中自动安装锁定版本的 Python 依赖。开发构建需要 Python，安装桌面发行包的用户不需要另装 Python。Windows 和 Linux 应分别在对应系统上构建，不支持跨系统交叉打包。

## 隐私说明

当前接入功能不等于业务内容端到端加密。明文 HTTP 实验不能防止网络上的窃听者读取内容；公网访问应使用正确验证的 HTTPS。即使使用 HTTPS，网关作为转发端仍可能读取解密后的业务内容。不要把连接成功理解为已经通过端到端隐私验收，也不能保证流量无法被识别。
