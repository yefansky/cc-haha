## 先记住五件事

1. 桌面主线是 Electron → 本地 Server → 会话 CLI → `QueryEngine` → `query()`；相似名字的 `agentSdkTypes.query`、`sessionManager` 里有占位实现，不能用文件名猜入口。
2. 官网新版已经纠正“四级压缩全部可用”的旧说法；Snip 和 Context Collapse 在本 fork 是 stub。流式工具执行也有启用条件。
3. 当前 fork 的工作区包含 Git/SVN、左右比较、文件编码保持和单文件编辑授权。仅按上游“Git diff 查看器”理解会漏掉关键约束。
4. 官网新增的原生 macOS 电脑操作方案，不等于本 fork 已实现；当前实际入口仍走 Python bridge。新增文档之间还有后文推翻前文的情况。
5. UI 显示、服务端运行态、真实端到端行为是三种证据。子代理找到测试文件、网关显示在线，都不能替代实际测试结果。

入口兼容：Codex 等 agent 从根 `AGENTS.md` 路由到这里；cc-haha / Claude 的项目指引加载器从根 [CLAUDE.md](../CLAUDE.md) 引用同一规则和本页。无需依赖运行时自动记忆开启，专题按需读取。

本机还保存[私人的 fork 研发历史](../文档/研发历史/README.md)：用户需求原文、task 留痕、技术路线与踩坑、任务和代码反向索引。修改已有功能前先查对应主题，再回到当前源码确认。该档案独立存放并被 Git 忽略；此页不内嵌私人原文，普通克隆可能没有该目录。

## 整体骨架

这是骨架，细节尚未展开。箭头表示主调用方向，事件与权限应答沿连接返回。

```mermaid
flowchart LR
  A[桌面或浏览器 UI] --> B[本地 Server 会话与通信]
  B --> C[会话 CLI 子进程]
  C --> D[QueryEngine 与 query 循环]
  D --> E[模型适配与请求]
  D --> F[工具 权限 子 Agent]
```

Electron 主进程另外管理系统能力、服务进程和网关凭据；浏览器通过 Host 接口的降级实现接入。这不是每个模块共用一个进程或一份状态。

## Agent 开始修改前

1. 先读根 [AGENTS.md](../AGENTS.md) 及目标目录更近的规则，运行 `git status --short`，保护已有改动。
2. 在仓库根执行 `python 代码地图/verify_snapshot.py`。如果源码哈希变化，对应结论需要重读；哈希未变也不代表行为测试通过。
3. `.codegraph/` 存在时优先 `codegraph explore "具体问题" --path "."`；随后用 `rg` 按本文路径与符号定位。无索引时按仓库约定建立，索引不能替代当前磁盘源码。
4. 沿“生产入口 → 状态变化 → 实际副作用 → 回传与展示”追链。查清 feature 开关、占位实现、平台和模型条件。
5. 遵循已有测试规范，修改后运行范围对应的检查；文档里的邻近测试只是入口，本次没有运行产品测试。
