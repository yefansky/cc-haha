## 原始设计中应保留的思想

### 1. 执行内核与使用界面分开

**官网设计**：[架构总览](来源/2026-09-09/index.md)、[Server](来源/2026-09-09/server.md) 把工具和推理执行放在 CLI 核心，Server 承接桌面/H5 等连接、会话与本机服务，Electron 承接系统壳能力。终端 CLI 也可以独立运行，“Server 是入口”不能扩大成所有调用路径都必须经过 Server。

**当前代码（桌面/headless 路径）**：`src/server/services/conversationService.ts:307` 构造会话 CLI 参数，`:470` 启动子进程；`src/cli/print.ts:2122`、`src/QueryEngine.ts:697`、`src/query.ts:221` 接入实际推理循环。交互终端由 `src/screens/REPL.tsx:2794` 直接调用 query。

**维护建议（归纳）**：界面异常先看事件/状态链；模型请求异常先看 query 依赖和协议转换；不要把修复放到名字相似的类型或 stub 文件。

### 2. 用可追溯的状态转移承接恢复

**官网设计**：[Agent 框架](来源/2026-09-09/agent-framework.md) 用异步生成器、状态对象和循环表示多轮模型/工具交互与恢复原因。

**当前代码**：`src/query.ts:243` 的 `queryLoop` 及 `:309` 的循环承接这些转移；`src/query/deps.ts:35` 将模型 I/O 接到生产依赖。

**维护建议（归纳）**：错误恢复要区分请求失败、工具已执行、权限等待、断线重放等阶段。随意在外层重发整条用户消息，可能重复产生实际副作用。生成器是一种实现机制；不要照抄官网关于其他框架或 ReAct “无法流式”的泛化比较。

### 3. 并发完成顺序不能污染上下文顺序

**官网简化**：把工具编排画成“只读并发、写入串行”。

**当前代码**：`src/services/tools/toolOrchestration.ts:98` 实际依赖 `isConcurrencySafe(input)`。`:31` 到 `:61` 允许并发结果先流出，但暂存 `contextModifier`，再按原 `tool_use` 顺序应用。新 `TrackFileChangesTool` 的只读/非并发声明提供直接反例。

**维护建议（归纳）**：工具的只读、可并发和权限是不同维度。增加工具或调整并发时要保留上下文应用顺序，而不只是检查最终返回值一样。

### 4. 前缀缓存是一种条件优化，不能当功能保证

**官网设计**：[多 Agent 实现](来源/2026-09-09/agent-internals.md) 解释 fork 子代理通过一致父消息前缀复用缓存，再附加各自任务。

**当前代码**：`src/tools/AgentTool/forkSubagent.ts:32` 先检查构建特性并排除非交互会话；`src/utils/betas.ts:257` 的 global cache 范围另有限制。桌面 `--print` 路径不能套用“默认 fork 缓存”模型。

**维护建议（归纳）**：保留公共前缀和身份的原始意图，但必须先核验路径是否启用、提供商是否支持。不能从代码中的 cache scope 推断真实服务端命中、跨组织共享或费用收益。
